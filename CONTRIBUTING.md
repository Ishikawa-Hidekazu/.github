# Contributing

Thank you for helping improve an Ishikawa Hidekazu open source project.

## Before You Start

Please read the target repository's README and local contribution guidance first. Repository-specific documentation overrides this organization-wide default.

Good contributions are small, focused, testable, and consistent with the project's documented safety boundary. Before opening an issue, check existing issues and confirm that the behavior is caused by the project rather than an upstream service.

## Issues

Use the affected repository's issue tracker for reproducible bugs, focused feature requests, and documentation gaps.

Include:

- the project version or commit;
- the operating system and relevant runtime version;
- minimal reproduction steps;
- expected and actual behavior;
- redacted output when it helps explain the problem.

Never post credentials, tokens, cookies, signed URLs, private content, account identifiers, raw transcripts, or customer data.

## Pull Requests

- Keep each pull request focused on one change.
- Explain the user-visible effect and any safety impact.
- Add or update tests when behavior changes.
- Run the checks documented by the target repository.
- Use English for public issues, pull requests, commits, and repository-facing documentation unless a file is explicitly localized.

Large features or changes to a project's safety boundary should be discussed in an issue before implementation.

By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
