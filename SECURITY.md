# Security Policy

## Reporting A Vulnerability

Do not report suspected vulnerabilities in a public issue.

Use GitHub private vulnerability reporting when the affected repository provides it. Otherwise, contact the maintainer through [ishikawa.co/contact](https://ishikawa.co/contact/) with a short notice that you have a security report.

Do not include credentials, tokens, cookies, signed URLs, private content, raw logs, transcripts, exploit details, or customer data in the initial message.

## What To Include

In a private report, include only what is necessary:

- the affected repository and version or commit;
- the affected command or feature;
- a minimal reproduction using synthetic or public-safe data;
- expected and observed behavior;
- potential impact.

Repository-specific security policies and supported-version statements override this organization-wide default.
